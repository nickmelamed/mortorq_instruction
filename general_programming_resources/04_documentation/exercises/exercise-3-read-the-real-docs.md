# Exercise 3: Read the Real Docs

## Goal
Practice all four reading habits from `concept.md`'s "Reading" section against real documentation you'll actually use this season, instead of a made-up example.

## Scenario
[docs.wpilib.org](https://docs.wpilib.org/en/stable/) is the reference this entire curriculum points you to constantly, and it's built the way most real technical documentation is: a getting-started guide up front, a much longer API reference behind it, and an explicit version selector, because the API genuinely changes between seasons. This exercise is entirely about navigating a real site, so nothing for you to fix.

## Steps
1. **Quickstart before reference.** Open the docs and find the getting-started material. This is the section meant to get a new user running something concrete, not the exhaustive class-by-class API listing. Name what you found and how you could tell it apart from the reference material.
   
2. **Search, don't scroll.** Pick any WPILib concept you already know the name of (command-based programming, PID, encoders — whatever you've heard mentioned) and use in-page or site search to jump straight to it instead of browsing menus top to bottom. Time yourself; under 30 seconds is the point.
   
3. **Signature before prose.** Find the API reference page for a motor-controller or sensor class you recognize, in whichever language your team uses. Before reading any of the prose description, look only at one method's signature — its name, its parameters, its return type — and write down what you think it does. Then read the actual description and check yourself against it.
   
4. **Check the version.** Find the version selector. What version are you currently looking at, and how would you go about confirming it matches the WPILib version your team's actual robot project is built against?

## Self-Check
- [ ] I can name the getting-started material and explain what distinguishes it from the full reference
- [ ] I found a real WPILib concept via search in under 30 seconds, not by browsing
- [ ] I wrote down a prediction from a method's signature alone, before reading its prose description, and compared it against the real description afterward
- [ ] I located the version selector and can state which version I was viewing

## Reflection
Each of these habits is about reading *less* of the documentation, not more. That's the actual point of treating reading as its own skill, separate from writing. The goal was never to read docs.wpilib.org cover to cover, and while it certainly never hurts to go through it, your aim shouldn't be to memorize the whole thing. It should be to find what you need in the given moment.
